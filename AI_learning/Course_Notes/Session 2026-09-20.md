## Other methods to improve retrieval
### Hyde
- When the user writes a query, the query goes through a process called **hyde**.  This process is performed by an LLM. The LLM will generate an answer without looking up the corpus. Then this generated response is then sent along with the query to the RAG for retrieval
- This method can be affected by hallucination in the first LLM response. This is probably a reason why it is considered not suitable for some domain data This is because the LLL response is purely based on its training data. If the query is asking for specific facts, then this might not work
- The mock answer enlarges the context that will improve the retrieval process, This does not look like a generally useful method from the description
### Query rewriting
- LLM will expand the query by making it more elaborate

### PII redaction in RAG
- emailids, phone number, credit card info etc
- This process can be part of either ingestion pipeline or retrieval pipeline.
![[Pasted image 20260920111622.png]]
- Microsoft library called presidio is used for PII redaction
- In the example shown in the session, the text contains a phone number. however it is classifying it as a datatime object
- it is also classifying the email id as both as an email and a url, but with different scores
- A sample implementation of this library can be found in [[oii_redaction_example.ipynb]]
- The demo used a spacy based model. This tends to misclassify entities.
- Transformer based models are better at this
### Loading pdf file
- pdf files pose the challenge of mix of text and images.

- We'll have to resort to concepts like OCR to handle complications
- The libraries we need for this is pymupdf and pytesseract
	- pymupdf is imported with the name **fitz**
- There is also a **pymupdf4llm**
